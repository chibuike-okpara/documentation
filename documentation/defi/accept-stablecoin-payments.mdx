---
title: "Accept Stablecoin Payments"
---

Accept payments in **USDT** and **USDC** and receive your settlement in fiat. You
create a payment intent for an amount, we give you a ready-to-use payment page,
and we notify you when the customer has paid, no wallet handling, addresses, or
blockchain details on your side.

<Note>
  Stablecoin payments are <b>not supported in test mode</b>. You must use a live
  API key to create and accept USDT/USDC payments.
</Note>

## How it works

<Steps>
  <Step title="Create a quote intent">
    Tell us how much to collect (in USD or GMD) and we return a payment link.
  </Step>
  <Step title="Send your customer to the payment page">
    Redirect them to the `link` from the response. They complete payment there.
  </Step>
  <Step title="Get notified when paid">
    We send a `charge.succeeded` webhook with how much has been paid so far.
  </Step>
</Steps>

## Create a quote intent

Creates a payment intent and returns a hosted payment page link.

<ParamField body="amount" type="number" required>
  The amount to collect.
</ParamField>

<ParamField body="currency" type="string" default="USD">
  Either `USD` or `GMD`. If you pass `GMD`, we convert it to USD automatically
  at the current exchange rate, the resulting intent is always in USD. Defaults
  to `USD`.
</ParamField>

<ParamField body="metadata" type="object">
  Any key–value data you want stored with the intent and returned to you later
  (for example your own order ID). Returned unchanged in webhooks.
</ParamField>

<ParamField body="callback_url" type="string">
  A URL to receive webhook notifications for this intent.
</ParamField>

<ParamField body="expires_at" type="string">
  Optional expiry time for the payment (ISO 8601).
</ParamField>

<Note>
  The minimum amount is **5 USD**. If you submit a `GMD` amount that converts to
  less than $5, the request is rejected with a message that includes the current
  exchange rate.
</Note>

<CodeGroup>

```typescript nodejs
const intent = await modempay.quoteIntents.create({
  amount: 10,
});
```

```bash cURL
curl -X POST https://api.modempay.com/v1/minting/intents \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 10
  }'
```

</CodeGroup>

<Note>
  Only `amount` is required. Add `metadata` if you want your own references
  echoed back in webhooks.
</Note>

**Response**

```json json
{
  "id": "00000000-0000-0000-0000-000000000000",
  "status": "pending",
  "amount": 10,
  "currency": "USD",
  "metadata": {},
  "business_id": "biz_xxxxxxxxxxxxxxxx",
  "account_id": "acct_xxxxxxxxxxxxxxxx",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z",
  "payment_link_id": null,
  "token": null,
  "link": "https://checkout.modempay.com/pay/quote/00000000-000000000000",
  "expiresAt": null,
  "callback_url": null
}
```

Send your customer to the `link`. The hosted page handles the payment and accepts
**USDT** or **USDC**. The intent starts with `status: "pending"`.

## Accepting payment

Your customer pays on the hosted page, you don't handle the payment method
yourself. A couple of things to design for:

<Warning>
  **A payment may arrive in more than one transfer, and may not match the full
  amount at first.** A customer can pay part of the amount, or pay across
  several transfers. Reconcile against the running total we send, rather than
  assuming a single full payment.
</Warning>

Two fields tell you what you need:

- **`amount`** — the total paid toward this intent so far. It accumulates across
  transfers; it is **not** the originally quoted amount.
- **`status`** — `partially_paid` while the total is below the quote, and
  `completed` once the full amount has been received.

The originally quoted amount is in **`metadata.usd_amount`**. A payment is
complete when `amount` reaches `metadata.usd_amount`, which is also when
`status` becomes `completed`.

## List quote intents

```bash cURL
curl https://api.modempay.com/v1/minting/intents \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Retrieve a quote intent

```bash cURL
curl https://api.modempay.com/v1/minting/intents/00000000-000000000000 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Returns the same shape as the create response, reflecting the latest state of the
intent.

## Webhooks

When a payment is received, we send a `charge.succeeded` event to your configured
webhook URL. You may receive it more than once for the same payment as the
running total grows.

<ParamField body="event" type="string">
  The event type, e.g. `charge.succeeded`.
</ParamField>

<ParamField body="payload" type="object">
  The charge object. Key fields below.
</ParamField>

<ParamField body="payload.amount" type="number">
  Total paid toward this charge so far, in USD. Accumulates across transfers.
</ParamField>

<ParamField body="payload.status" type="string">
  `partially_paid` until the full amount is received, then `completed`.
</ParamField>

<ParamField body="payload.metadata.usd_amount" type="number">
  The originally quoted amount, in USD. Compare `amount` against this to know
  when the charge is fully paid.
</ParamField>

<ParamField body="payload.metadata.payment_history" type="array">
  Each individual payment received, with `amount_paid_usd`, `amount_paid_gmd`,
  and `timestamp`.
</ParamField>

```json json
{
  "event": "charge.succeeded",
  "payload": {
    "id": "00000000-0000-0000-0000-000000000000",
    "type": "payment",
    "status": "partially_paid",
    "amount": 10,
    "currency": "USD",
    "payment_method": "TRC20",
    "reference": "MP-XXXXXXXX-XXXXXX-XXXXXXXX",
    "transaction_reference": "MP-XXXXXXXX-XXXXXX-XXXXXXXX",
    "account_id": "acct_xxxxxxxxxxxxxxxx",
    "business_id": "biz_xxxxxxxxxxxxxxxx",
    "test_mode": false,
    "metadata": {
      "quote_id": "11111111-1111-1111-1111-111111111111",
      "usd_amount": 20,
      "gmd_rate": 74.8814,
      "fee": 0.2,
      "fee_currency": "USD",
      "fee_bearer": "business",
      "payment_history": [
        {
          "amount_paid_usd": 10,
          "amount_paid_gmd": 741,
          "timestamp": "2026-01-01T00:00:00.000Z"
        }
      ]
    },
    "createdAt": "2026-01-01T00:00:00.000Z",
    "updatedAt": "2026-01-01T00:00:00.000Z"
  }
}
```

In this example, `amount` is `10` against a quoted `metadata.usd_amount` of `20`,
so `status` is `partially_paid`. When the remaining `10` is paid, `amount`
becomes `20` and `status` becomes `completed`.

<Warning>
  Because payment can arrive in multiple parts, you may receive more than one
  `charge.succeeded` event for the same charge as `amount` increases. Make your
  handler **idempotent** and key your records on the charge `id` (or your own
  `metadata` reference), using `amount` as the running total.
</Warning>

<Note>
  For verifying that a webhook genuinely came from Modem Pay (signature header
  and validation), see the [Webhooks guide](/documentation/core/webhooks).
</Note>

## Reconciliation checklist

- Store the charge `id` (and your own reference in `metadata`) when you create
  the intent.
- On each `charge.succeeded`, read `payload.amount` (USD) and compare it to
  `payload.metadata.usd_amount`.
- Treat the payment as complete when `amount` reaches `usd_amount` **or** when
  `status` is `completed`.
- Use `payload.metadata.payment_history` if you need the individual payments.
- Handle repeated webhooks for the same `id` idempotently.
