---
title: "Checkout pop-up"
description: "Open Modem Pay's checkout in a pop-up on your page, and react to the result in JavaScript."
---

The pop-up lets customers pay without leaving your site. You open it with one function call and get told when the payment finishes or the customer closes it.

<Tip>
  Just need a button? The [pay button](/documentation/payments/drop-in) wraps this pop-up in a single HTML tag.
</Tip>

## Add it to your page

```html
<link rel="stylesheet" href="https://api.modempay.com/dist/main.css" />
<script src="https://api.modempay.com/js/v1.js"></script>

<button type="button" onclick="pay()">Pay now</button>

<script>
  function pay() {
    const modal = ModemPayCheckout({
      public_key: "pk_test_...",
      amount: 450,
      title: "Course payment",
      customer_email: "customer@example.com",
      metadata: { order_id: "1042" },
      callback: (transaction) => {
        // The payment finished. Confirm it on your server before delivering.
        fetch("/orders/1042/confirm", {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({ transaction_id: transaction.id }),
        });
        modal.close();
      },
      onClose: (cancelled) => {
        if (cancelled) console.log("Customer closed checkout without paying.");
      },
    });
  }
</script>
```

<Warning>
  This code runs in the browser, so it uses your **public** key. Never put your secret key here.
</Warning>

## Options

| Option | What it does | Example |
| --- | --- | --- |
| `public_key` | Your public key. Required. | `"pk_test_…"` |
| `amount` | Amount to charge, in GMD. Required. | `450` |
| `currency` | Defaults to `GMD`. | `"GMD"` |
| `payment_methods` | Which kinds of method to offer. | `"wallet,card"` |
| `title` | Short title shown at checkout. | `"Course payment"` |
| `description` | Longer description. | `"Access to premium content"` |
| `customer` | An existing [customer](/documentation/core/customers) ID. Their saved payment methods are offered. | `"7e1908bb-…"` |
| `customer_name`, `customer_email`, `customer_phone` | Fill in checkout for the customer. | `"Awa Jallow"` |
| `metadata` | Your own data. Comes back on the transaction and webhook. | `{ "order_id": "1042" }` |
| `return_url` | Redirect here after payment, instead of calling `callback`. | `"https://yoursite.com/thanks"` |
| `cancel_url` | Redirect here on cancel, instead of calling `onClose`. | `"https://yoursite.com/cart"` |
| `callback` | Called with the transaction when the payment finishes. | `(transaction) => {}` |
| `onClose` | Called when the pop-up closes. `cancelled` is `true` if the customer didn't pay. | `(cancelled) => {}` |

## Redirects or callbacks?

- If you set `return_url`, the customer is redirected after paying and `callback` is **not** called.
- If you set `cancel_url`, the customer is redirected on cancel and `onClose` is **not** called.

Use the callbacks to stay on the page, like a single-page app. Use the URLs for a classic "thank you" page.

<Note>
  `callback` fires as soon as the payment finishes, while the pop-up may still be open. Close it with `modal.close()` when you're ready.
</Note>

## Confirm on your server

A browser callback can be faked. Before you deliver anything, check the payment on your server, either from the `charge.succeeded` [webhook](/documentation/core/webhooks) or by [looking it up](/documentation/core/transactions#get-a-transaction) with your secret key.

See a full example with a "verifying…" state: [CodePen](https://codepen.io/mercury-sms/embed/EaYNGOv?default-tab=html%2Cresult).
