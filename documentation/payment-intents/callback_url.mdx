---
title: "Callback URL"
description: "Send one payment's events to its own URL, instead of your account webhook."
---

Set `callback_url` when you create a payment intent, and that payment's events (`charge.succeeded`, `charge.failed` and the rest) go to that URL **instead of** your account [webhook](/documentation/core/webhooks).

This is useful when one Modem Pay account serves several systems, like a marketplace where each shop has its own server.

<CodeGroup>
```javascript nodejs
const intent = await modempay.paymentIntents.create({
  amount: 450,
  callback_url: "https://shop-42.example.com/modempay",
});
```
```python python
intent = modem_pay.payment_intents.create(params={
    "amount": 450,
    "callback_url": "https://shop-42.example.com/modempay",
})
```
```php php
$intent = $modemPay->paymentIntents()->create([
    'amount' => 450,
    'callback_url' => 'https://shop-42.example.com/modempay',
]);
```
```bash cURL
curl -X POST https://api.modempay.com/v1/payments \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{ "data": { "amount": 450, "callback_url": "https://shop-42.example.com/modempay" } }'
```
</CodeGroup>

The body is the same as a webhook: `{ "event": "...", "payload": { ... } }`. Retries work the same way too: up to 3 more tries, 10 minutes apart.

## Verify a callback

Callbacks are signed differently from webhooks. There's no webhook secret here. Instead, the signing key is the **SHA-256 hash of your secret API key**, as lowercase hex.

| Header | What it holds |
| --- | --- |
| `x-modem-signature` | HMAC-SHA512 of the raw body, made with `sha256(secret_key)`. |
| `x-modem-signature-key` | The last 4 characters of the secret key that signed it. |

<CodeGroup>
```javascript nodejs
import crypto from "crypto";

const signingKey = crypto
  .createHash("sha256")
  .update(process.env.MODEMPAY_SECRET_KEY)
  .digest("hex");

// rawBody: the request body exactly as received
const event = modempay.webhooks.composeEventDetails(
  rawBody,
  req.headers["x-modem-signature"],
  signingKey,
);
```
```python python
import hashlib, hmac, os

signing_key = hashlib.sha256(os.environ["MODEMPAY_SECRET_KEY"].encode()).hexdigest()
expected = hmac.new(signing_key.encode(), raw_body, hashlib.sha512).hexdigest()
valid = hmac.compare_digest(expected, request.headers.get("x-modem-signature", ""))
```
```php php
$signingKey = hash('sha256', getenv('MODEMPAY_SECRET_KEY'));

$event = $modemPay->webhooks()->composeEventDetails(
    file_get_contents('php://input'),
    $_SERVER['HTTP_X_MODEM_SIGNATURE'] ?? '',
    $signingKey
);
```
</CodeGroup>

<Note>
  Callbacks are signed with your **newest active** secret key on that account. After you [roll a key](/documentation/authentication#roll-a-key), callbacks are signed with the new one. If you keep several keys, use `x-modem-signature-key` to pick the right one.
</Note>

Use an HTTPS URL. As with webhooks, use the raw request body, and reply `200` quickly.
