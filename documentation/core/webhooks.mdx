title: "Webhooks"
description: "Get told the moment a payment, payout, customer or invoice changes."
---

A webhook is a `POST` request Modem Pay sends to your server when something happens, like a payment succeeding. Use webhooks to mark orders paid, send receipts and update your records, even when the customer closes their browser.

## Set up your endpoint

<Steps>
  <Step title="Create a POST endpoint">
    It must be public and use HTTPS, for example `https://yoursite.com/webhooks/modempay`. Local addresses like `localhost` are refused. To test locally, use the [CLI](/documentation/cli).
  </Step>
  <Step title="Add it in the dashboard">
    Go to **Developers → Webhooks** and enter the URL. You can have one webhook per account in test mode and one in live mode.
  </Step>
  <Step title="Copy the signing secret">
    You'll use it to check that each request really came from Modem Pay. For safety, revealing it asks for a one-time code sent to your email.
  </Step>
  <Step title="Reply 200 quickly">
    Return `200` as soon as you've checked the signature, then do the slow work (emails, database updates) afterwards.
  </Step>
</Steps>

<Warning>
  **Saving the webhook URL creates a new signing secret.** This happens when you change the URL, and when you turn a disabled webhook back on. After any change, copy the new secret to your server, or every signature check will fail.
</Warning>

## Verify the signature

Every webhook has an `x-modem-signature` header. It's an HMAC-SHA512 of the **exact request body**, made with your webhook signing secret. Check it before you trust anything in the request.

<Warning>
  **Use the raw body.** Don't parse the JSON and turn it back into a string. Many frameworks change spacing or key order when they do that, and the signature no longer matches. This is the most common reason signature checks fail, especially on Firebase, Vercel and other serverless platforms.
</Warning>

<CodeGroup>
```javascript Node (Express)
import express from "express";
import ModemPay from "modem-pay";

const modempay = new ModemPay(process.env.MODEMPAY_SECRET_KEY);
const app = express();

// express.raw keeps the body exactly as it was sent.
app.post("/webhooks/modempay", express.raw({ type: "application/json" }), (req, res) => {
  let event;
  try {
    event = modempay.webhooks.composeEventDetails(
      req.body.toString("utf8"),
      req.headers["x-modem-signature"],
      process.env.MODEMPAY_WEBHOOK_SECRET,
    );
  } catch {
    return res.status(400).send("Invalid signature");
  }

  res.sendStatus(200);

  switch (event.event) {
    case "charge.succeeded":
      // mark the order paid
      break;
    case "transfer.failed":
      // tell your team
      break;
  }
});
```

```python Python (Flask)
import hashlib, hmac, json, os
from flask import Flask, request

app = Flask(__name__)

@app.post("/webhooks/modempay")
def webhook():
    raw = request.get_data()  # the raw bytes, not request.json
    expected = hmac.new(
        os.environ["MODEMPAY_WEBHOOK_SECRET"].encode(), raw, hashlib.sha512
    ).hexdigest()

    if not hmac.compare_digest(expected, request.headers.get("x-modem-signature", "")):
        return "Invalid signature", 400

    event = json.loads(raw)
    if event["event"] == "charge.succeeded":
        pass  # mark the order paid
    return "", 200
```

```go Go
func modemWebhook(w http.ResponseWriter, r *http.Request) {
	body, err := io.ReadAll(r.Body)
	if err != nil {
		http.Error(w, "bad request", http.StatusBadRequest)
		return
	}

	mac := hmac.New(sha512.New, []byte(os.Getenv("MODEMPAY_WEBHOOK_SECRET")))
	mac.Write(body)
	expected := hex.EncodeToString(mac.Sum(nil))

	if !hmac.Equal([]byte(expected), []byte(r.Header.Get("x-modem-signature"))) {
		http.Error(w, "invalid signature", http.StatusBadRequest)
		return
	}

	w.WriteHeader(http.StatusOK)
	// json.Unmarshal(body, &event) and handle it
}
```

```javascript Node (no SDK)
import crypto from "crypto";

function isFromModemPay(rawBody, signature, secret) {
  const expected = crypto.createHmac("sha512", secret).update(rawBody).digest("hex");
  return (
    typeof signature === "string" &&
    signature.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signature))
  );
}
```

### Still failing?

- Are you using the secret from the **same mode**? Test and live webhooks have different secrets.
- Did you change the webhook URL recently? That creates a new secret.
- Are you using the **webhook signing secret**, not your API secret key?
- Are you checking the **raw** body? Log `rawBody.length` and compare it with the `Content-Length` header.

## Retries

If your endpoint doesn't reply with a `2xx` status, or times out, Modem Pay tries again **up to 3 more times, 10 minutes apart**.

You can see every delivery, with your server's response, in **Developers → Webhooks → Events**. From there you can **resend** any event by hand.

### Handle duplicates

Because of retries, you may get the same event more than once. Make your handler safe to run twice. For example, before marking an order paid, check it isn't already paid. The `payload.id` stays the same across retries.

## Webhooks or `callback_url`?

You can also pass a `callback_url` when you create a payment intent. Modem Pay then sends that payment's events to that URL **instead of** your webhook. This is handy when different payments belong to different systems.

| | Webhook | `callback_url` |
| --- | --- | --- |
| Set in | Dashboard, once | Each request |
| Receives | Every event on the account, unless the object has a `callback_url` | Events for that one payment |
| Signed with | Your webhook signing secret | A hash of your secret API key |

See [Callback URL](/documentation/payment-intents/callback_url) for how to verify those.

## Good practice

- Fulfil orders on `charge.succeeded`, not when the customer lands on your `return_url`.
- Check `payload.amount` and `payload.currency` match what you expected.
- Check `payload.test_mode` is `false` before shipping real goods.
- Reply fast. Put slow work in a background job.
