When a request fails, Modem Pay returns an HTTP status of 400 or higher and a JSON body with a `message` you can show or log. Many errors also have a `code` your code can check.

```json
{
  "message": "This API key does not have the 'refunds:write' permission required for this request.",
  "code": "insufficient_scope",
  "required_scope": "refunds:write"
}
```

<Tip>
  Check `code` in your logic, not `message`. Messages are written for people and may change. Codes don't.
</Tip>

## Status codes

| Status | Meaning | What to do |
| --- | --- | --- |
| `400` | The request is missing something or has a wrong value. Validation errors list every problem in `message`, separated by commas. | Fix the request. Don't retry it unchanged. |
| `401` | No API key, or the key is wrong, revoked or expired. | Check the key. See [API keys](/documentation/authentication#when-a-key-is-refused). |
| `403` | The key works but isn't allowed to do this, or the IP address isn't allowed. | Add the permission or IP address, or use another key. |
| `404` | The thing you asked for doesn't exist, or belongs to another account or mode. | Check the ID, and that you're using a test key for test data and a live key for live data. |
| `409` | The request clashes with the current state, for example a duplicate. | Fetch the latest state before trying again. |
| `410` | The endpoint has been removed. | Move to the endpoint named in `message`. |
| `413` | The request body is too large. | Send less data per request. |
| `429` | Too many requests. | Wait, then retry. See [Rate limits](#rate-limits). |
| `500` | Something went wrong on our side. | Retry with backoff. If it keeps happening, email support. |
| `503` | A service we depend on is busy or unavailable. | Retry shortly. |

## Error codes you may see

| `code` | Status | Meaning |
| --- | --- | --- |
| `authorization_invalid` | 401 | The `Authorization` header isn't `Bearer <secret key>`. |
| `api_key_missing` | 401 | The header has no key. |
| `public_key_not_allowed` | 401 | A public key was sent where a secret key is needed. |
| `api_key_invalid` | 401 | The key doesn't exist or doesn't match the mode. |
| `api_key_revoked` | 401 | The key was revoked. |
| `api_key_expired` | 401 | The key has expired. `expired_at` says when. |
| `ip_not_allowed` | 403 | The request came from an IP address that isn't on the allowlist. |
| `insufficient_scope` | 403 | The key is missing the permission in `required_scope`. |
| `route_not_permitted` | 403 | Restricted keys can't call this endpoint. |
| `per_transfer_limit_exceeded` | 403 | A payout is above the key's per-payout limit. |
| `daily_transfer_limit_exceeded` | 403 | The payout would take the key over its daily limit. |
| `DAILY_LIMIT_EXCEEDED` | 429 | The payout would go over the account's daily limit. See [Daily limits](/documentation/payouts/daily-limits). |
| `RATE_LIMIT` | 429 | Too many payout requests in a short time. |
| `VELOCITY_LIMIT` | 429 | The account has sent too much value in the current window. |
| `CONCURRENCY_LIMIT` | 429 | Too many payouts are already being processed. |
| `ACCOUNT_THROTTLED` | 429 | Payouts are paused for a while after many rejected payouts. |
| `INSUFFICIENT_LIQUIDITY` | 503 | Payout capacity is used up for now. Retry shortly. |
| `BATCH_TOO_LARGE` | 400 | A bulk payout has too many items. The limit is 1,000. |

## Rate limits

Requests to `/v1` are limited per business over a rolling 15-minute window. Payouts have their own, stricter limits to protect your balance.

When you hit a limit you get a `429`:

```json
{
  "message": "Too many requests from this account, please try again in 312 seconds.",
  "retryAfter": 312
}
```

Wait `retryAfter` seconds before trying again. Responses also carry the standard `RateLimit` headers, so you can slow down before you reach the limit.

Need a higher limit? Email [info@modempay.com](mailto:info@modempay.com) with your expected volume.

## Retries in the SDKs

The SDKs retry failed requests that are likely to be temporary, such as network errors and `5xx` responses. They try up to **3 times** by default, waiting a little longer each time.

<CodeGroup>
```javascript nodejs
const modempay = new ModemPay(process.env.MODEMPAY_SECRET_KEY, {
  maxRetries: 3, // 0 turns retries off
});
```
```python python
modem_pay = ModemPay(api_key="sk_test_...", config={"maxRetries": 3})
```
</CodeGroup>

To hide the retry log lines but keep retrying, set `RETRY_LOGGING=false` in your environment.

<Warning>
  Before retrying a payout yourself, send the same `Idempotency-Key` header as the first attempt. Then a retry can never pay someone twice. See [Mobile money payouts](/documentation/payouts/mobile-money#send-a-payout).
</Warning>

## Timeouts

SDK requests time out after **60 seconds** by default. You can change this (in seconds):

<CodeGroup>
```javascript nodejs
const modempay = new ModemPay(process.env.MODEMPAY_SECRET_KEY, {
  timeout: 20,
});
```
```python python
modem_pay = ModemPay(api_key="sk_test_...", config={"timeout": 20})
```
</CodeGroup>

If a payment or payout request times out, don't assume it failed. Look it up by ID or reference first, or wait for the webhook.
